# 知识库索引与 Agent 工作流

申报参谋采用有明确工具边界的工作流 Agent。大模型负责读取语义和生成有引用的文案，程序负责资格判断、数值比较、截止日期计算和文件导出。每次成功模型请求都记录工具名、实际返回模型名、token用量、耗时和response ID；不保存API Key。

## 本地知识库索引

1. TXT/MD/JSON按UTF-8读取；DOCX提取段落与表格；文字型PDF提取各页文字并加入页码。扫描件无足够文字会明确拒绝。单文件12MB，总文本每份12万字符上限是输入约束，不是已验证性能承诺。
2. 按段落累积至约700字符，长段落按700字符切分，重叠100字符。政策块为P001等，企业块为E001等。原文、块ID、完整输入及SHA256随分析记录保存在本地SQLite。
3. 查询与块分别按连续中文双字构成集合，按交集数量降序召回前4至6块。并列时保留原文顺序。当前实现是轻量词法召回，没有向量Embedding服务、没有声称训练或部署向量模型。
4. 问答仅提交当前记录的5块召回证据；文案提交选中项目结构、企业画像和6块证据。模型返回引用ID，程序检查引用ID属于本轮召回集合。
5. 导出Word包含正文引用与完整引用块，JSON包含原始输入、完整索引和源文件哈希，可用于复核。引用存在性不等于每一句语义都已验证，文案事实仍需人工审阅。

## 核心工作流

| 阶段 | Agent调用或程序工具 | 结果与门禁 |
|---|---|---|
| 读取资料 | extract_file / chunks | 类型、大小和文本上限校验；建立P/E索引 |
| 政策拆解 | DeepSeek function calling submit_policy | 多项目、硬条件、资助上限、节点、附件和其他硬资格条件 |
| 原文校验 | validate_policy | 项目名、条件引用、条件值、资助值与日期必须在原文；日期带+08:00 |
| 企业画像 | JSON直接读取；非JSON用submit_profile | 字段值须附原文证据；缺失信息不推测 |
| 资格匹配 | match | Decimal比较、未知状态、等权分数与差距值 |
| 日历 | calendar / check_alerts | 北京时间，网报和纸质独立节点，7/3/1天提醒窗口 |
| 写作 | retrieve + submit_draft | 不少于1000个中文字的正文；规划与事实区分；引用ID校验 |
| 问答 | retrieve + submit_answer | 仅用当前本地资料回答，显示证据块 |
| 导出 | export / draft_doc / checklist / ics | Word、MD、CSV、ICS、JSON与SHA256整包 |

此版本的控制器按固定顺序执行工具，采用受约束的Agent流程，不允许模型执行任意代码、联网浏览或改变企业真实档案。模型未返回正确工具调用、原文依据不存在、文案不足1000字时，任务会失败并提示重试，不以固定示例代替真实模型结果。

## 分数与资格口径

匹配度 = 通过条件数 / 已提取数值与文本条件总数 × 100，四舍五入为整数。条件等权，未提供数据按未通过计分并单独标为“待核实”。只要有一项失败则“不符合”；没有失败但有未知字段或无法自动表示的硬资格条件，则“待核实”；其余为“符合形式条件”。分数不是获批概率，主体形式条件和官方评审意见不同，截止窗口另在日历显示。

同一字段多重条件、政策中的复杂“或”关系、累计年度/关联企业口径、财务口径转换等需要人工确认。本版本没有宣称对任意政策达到无遗漏或全自动法律审查。非JSON企业档案的事实提取也会消耗模型调用。

## 提醒接口与扩展

本地服务每60秒扫描SQLite记录；到7、3、1天窗口分别生成一次提醒，按政策哈希、项目、节点和窗口去重。启动客户端时会检查当前窗口，不会重新发送错过的所有窗口。Windows原生窗口弹出提醒，浏览器通知需授权且页面保持打开；ICS提供三个DISPLAY闹铃，由支持此特性的日历应用负责触发。

移动端和微信预留接口契约：可以将本地提醒事件 `{policy_hash, project, label, deadline, reminder_days, raised_at}` 交给外部adapter。建议adapter实现幂等键、重试队列、推送失败记录和用户自选联系人。当前交付未配置微信、Webhook、短信或移动端凭证，未向任何联系人发送消息，不能将接口设计宣传为已验证推送能力。
